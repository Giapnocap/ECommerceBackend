# Operations Runbook

This runbook covers Phase 3 recovery procedures. Operations endpoints require an authenticated
Admin. Use the same `X-Correlation-ID` for related investigation requests and change records.

## Outbox Dead Letters

1. Check `/health/ready`. A degraded result means dead letters exist; an unhealthy result can also
   indicate an old pending backlog.
2. List messages with `GET /api/operations/outbox/dead-letters?page=1&pageSize=20`.
3. Fix the downstream cause before retrying. Do not repeatedly re-drive a message while SMTP or
   the target provider is still unavailable.
4. Re-drive one message with
   `POST /api/operations/outbox/dead-letters/{id}/redrive`.
5. Confirm the message disappears from the dead-letter list and watch `outbox.messages.processed`.

Re-drive is idempotent and never changes a successfully processed message. It resets the attempt
counter and schedules the message immediately. The payload is not returned by the operations API.
Every successful re-drive writes an audit event in the same database transaction.

Rollback: stop re-driving. Set `Outbox__Enabled=false` and restart only when delivery itself is
causing damage; this pauses all notifications but does not remove queued data.

## Upload Reconciliation

Always run dry-run first:

```http
POST /api/operations/uploads/reconcile
Content-Type: application/json

{"deleteOrphans":false,"maxDeletes":50}
```

`missingFiles` are database rows whose files are absent. They are reported only and must be
investigated or restored from backup. `orphanFiles` exist on disk without a database row. Cleanup
only deletes names generated by this application, older than `Uploads__ReconciliationGraceMinutes`,
and never exceeds `Uploads__MaxReconciliationDeletes` or the request limit.

After reviewing the dry-run result, repeat with `deleteOrphans=true`. File storage and SQL Server
cannot share one transaction: if the request fails after deleting files, rerun dry-run and inspect
the audit log. Never manually delete referenced files from the upload mount.

## Audit Investigation

Query `GET /api/operations/audit-events` and filter by `actorUserId`, exact `action`, exact
`entityType`, `from`, or `to`. Match `correlationId` with Serilog request logs. Audit metadata is
bounded and must never contain passwords, tokens, outbox payloads, webhook bodies, or connection
strings.

Important action names:

- `user.role.assign`
- `product.create`, `product.update`, `product.delete`
- `category.create`, `category.update`, `category.delete`
- `product.image.upload`, `product.image.delete`
- `order.status.update`
- `outbox.dead_letter.redrive`
- `uploads.orphans.delete`

Audit rows are append-only operational evidence. Do not update or delete them during incident
handling. Database retention/archival must be introduced as a separate reviewed policy.

## Metrics

The application emits .NET `Meter` instruments that a configured metrics collector can consume:

- `outbox.messages.processed`
- `outbox.messages.failed`
- `outbox.messages.dead_lettered`
- `outbox.dead_letters.redriven`
- `audit.events.enqueued`
- `uploads.orphans.deleted`
- `orders.expired`
- `orders.expiration.failed`
- `catalog.queries`
- `catalog.query.duration` (milliseconds)
- `catalog.query.result_count`

Alert on any dead-letter increment, sustained outbox failures, overdue order-expiration readiness,
or unexpected spikes in privileged audit actions.

Catalogue metrics use bounded tags only: `catalog.has_search`, `catalog.has_category` and
`catalog.sort`. Search text is never emitted. Establish p50/p95 latency and query-volume baselines
against production-like data before adding SQL full-text search, new indexes or response caching.
Any cache proposal must first define invalidation for product, category and image mutations.
